# Правила участия в проекте

## Порядок внесения изменений

1. Получите актуальные изменения основной ветки: `git switch main` и `git pull --ff-only`.
2. Создайте отдельную ветку: `git switch -c feature/short-description`.
3. Внесите изменения и при необходимости обновите документацию.
4. Проверьте `git diff` и `git status`: в коммит должны попасть только нужные файлы.
5. Создайте коммит с кратким описанием изменений.
6. Отправьте ветку: `git push -u origin feature/short-description`.
7. Откройте Pull Request в `main`. Опишите цель, изменения и выполненные проверки.
8. Проверьте итоговый diff и устраните замечания перед слиянием.
9. После слияния удалите рабочую ветку и обновите локальную `main`.

Для лабораторной работы №0 используется ветка `develop` и сообщение коммита `Initial project setup`.

## Требования к материалам

- Используйте Markdown для документации и понятные имена файлов.
- Храните отчёт каждой работы в `labN/labN_report.md`.
- Описывайте реально выполненные действия и наблюдаемые результаты.
- Объясняйте назначение команд; указывайте возникшие ошибки и способы их решения.
- Не добавляйте пароли, токены, приватные SSH-ключи и служебные файлы операционной системы.
- Проверяйте относительные ссылки и читаемость документации перед созданием Pull Request.
